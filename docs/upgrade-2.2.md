# v2.2.0 実装と検証

## 追加した機能

- AND/OR検索（既定PHRASEは互換維持、タイトル・本文を横断、認可後に絞り込み）
- 標準バックアップの一覧・読み取り（API独自スナップショットと区別）
- 添付の一覧・読み取り・ローカル保存・新規アップロード・履歴へ移す削除
- notimestampによる更新日時維持（競合確認・スナップショット・監査ログは継続）
- HTTPSの管理者画面から非公開保存先の初期設定とキーの発行・失効
- Claude DesktopのMCPB配布。利用者によるターミナルやNodeの手動導入は不要
- API URLのquery route対応。mod_rewrite/PATH_INFO不要

## 保存と認可

初期設定画面はPukiWikiの管理者パスワードで認証する。15分のセッション、CSRF検証、ログイン時のセッションID再生成、no-storeとフレーム埋め込み禁止を適用。
HTTPSのみ（localhost試験は例外）。既存config.local.phpや環境変数による設定を初期設定で上書きしない。保存先の移設は行わない。
Web公開領域外の実パスと書込可否を検査し、公開領域内への自動フォールバックはしない。Aliasなど追加公開設定がある環境では管理者が非公開であることを確認する。
キーはハッシュだけを保存し、発行画面で一度だけ生キーを表示する。キー書換えはロックと一時PHPファイルのrenameで行い、CLIと画面でKeyStoreを共有。

添付変更は既存writeキーに自動で許可しない。管理者がattachments_writeを明示付与したキーだけが、Wikiユーザーの編集可能な既存ページで実行できる。
ページの認可・凍結・保護に加えて添付自身の凍結も確認する。削除はSHA256一致を必須とし、標準の「16進ページ名_16進ファイル名.履歴番号」へ移動する。
既存の添付は上書きしない。APIのロックはWeb UIの添付操作と共通ではないため、同じ添付の同時操作は避ける。

添付変更はページ本文を変更しない。添付変更自体ではページmtime・RecentChanges・メール通知を更新しない。操作はAPI監査ログに残る。
履歴の取得は既存の閲覧可能ページに限定。削除済みページの履歴はWeb UIの管理操作で扱う。

## 転送とクライアント

添付転送は最大5 MiB、API JSONは既存のサイズ上限内。新規アップロードの形式はAPIリファレンス参照。
MCPBには実装とマニフェストのみを同梱し、生キーやユーザー設定を含めない。キーはsensitiveなユーザー設定として環境変数で渡す。
ローカルファイル操作はユーザーが指定した添付用フォルダだけに限定し、ダウンロード先は排他的作成で上書きを防ぐ。
サーバー応答のSHA256を確認する。画像/テキスト/バイナリリソースの表示可否はクライアントによる。

## 配布

開発者が `python3 tools/build-release.py` を実行すると `dist/` に本番ZIP、MCPB、SHA256一覧を生成する。
ZIPは許可リストから組み立て、test/・data/・config.local.php・run.sh・開発環境を含めない。
ライセンスはGPL-2.0-or-later。ソースは本リポジトリ、MCPBのソースも同梱する。
新規公開・FTPデプロイ・git pushは今回のローカル実装作業と別の操作。

## 検証手順（開発者向け）

テストはiCloud上では実行しない。APIとMCPを一時領域へコピーし、統合テストには使い捨てのPukiWiki 1.5.4を指定する。

- `php rest-api-v2/test/unit_test.php`
- `php rest-api-v2/test/features_test.php`
- `PKWK_ROOT=/使い捨ての本体 php rest-api-v2/test/integration_test.php`
- `PKWK_ROOT=/使い捨てのサイト php rest-api-v2/test/site_integration_test.php`
- `python3 rest-api-v2/test/browser_setup_test.py /使い捨ての本体`
- `node --test pukiwiki-mcp/test/*.test.mjs`
- 全PHPの構文検査、MCPBマニフェストの公式v0.3 JSON Schema検証、配布ZIPの内容検査

公開サイトへの書き込み、Windowsの実機動作、ホスティングごとのWAF/リバースプロキシ構成は別途検証が必要。
